# MorsePad — отчёт о тестировании мультитача

Версия приложения: 1.0 · Дата: 2026-10-11

> **Статус.** Разделы 1–3 — автоматические тесты, выполненные на JVM и на эмуляторе Android
> настоящими многоточечными `MotionEvent`. ТЗ (п. 5.3) требует подтверждения на реальном
> устройстве: симуляция не заменяет физические пальцы. Раздел 4 — протокол ручной проверки
> на телефоне с таблицей для результатов; его нужно пройти до приёмки.

## 1. Уровни проверки

| Уровень | Что проверяется | Где |
|---|---|---|
| Ядро (JVM) | Логика `InputEngine` на абстрактных событиях указателей: все комбинации, порядки, отмены, повторы, 5000 случайных аккордов | `core/src/test/.../input/InputEngineTest.kt` |
| Компонент на устройстве | Реальная панель `ChordPad` в Compose получает `ACTION_DOWN / POINTER_DOWN / POINTER_UP / UP / CANCEL` | `app/src/androidTest/.../ChordPadMultitouchTest.kt` |
| Сквозной, через систему ввода | Настоящее приложение; события идут через `InputDispatcher` (`UiAutomation`), проверяется итоговый текст | `app/src/androidTest/.../InputPipelineLatencyTest.kt`, `EditorFlowTest.kt` |

## 2. Соответствие требованиям п. 11.2

| Требование ТЗ | Тест(ы) | Результат |
|---|---|---|
| Одновременное нажатие пяти клавиш | `everyCombinationOfOneToFiveFingersCommitsItsMask` (вкл. `11111`), `everyReleaseOrderOfFiveFingersGivesTheSameChord` | ✅ |
| Все комбинации из 1, 2, 3, 4 клавиш | `everyCombinationOfOneToFiveFingersCommitsItsMask` — все 31 маска; JVM: `every one to five key combination commits exactly its mask` | ✅ |
| Разное время начала нажатия | `fingersLandingAtDifferentTimesFormOneChord` (180/40/300 мс), JVM: `fingers may start at different times` | ✅ |
| Разный порядок отпускания | `everyReleaseOrderOfFiveFingersGivesTheSameChord` — все 120 перестановок 5 пальцев; JVM: то же | ✅ |
| Быстрое чередование аккордов | `rapidAlternatingChordsLoseNothing` — 400 случайных аккордов с шагом 16 мс; сквозной `burstTypingLosesNothing` — 300 аккордов через систему ввода; JVM — 5000 аккордов с переиспользованием id | ✅ 0 потерь |
| Отмена касания операционной системой | `systemCancelDropsTheChordAndInputRecovers` (`ACTION_CANCEL`), `singlePointerCancelledBySystemIsRemoved` (`FLAG_CANCELED`) | ✅ |
| Сворачивание приложения во время нажатия | `chordHeldWhileTheAppLosesForegroundIsDropped` (палец удерживается, активность уходит в `onPause`, затем палец отпущен — символа нет, следующий аккорд работает) | ✅ |
| Различать касания по идентификаторам | `keyReleasedEarlyStaysInTheChord`, JVM: `reused pointer id inside one cycle keeps both keys` | ✅ |
| Не объединять касания вне пяти клавиш | `touchesOutsideThePadDoNotJoinTheChord` | ✅ |
| Не терять состояние при изменении порядка отпускания | `nothingIsCommittedWhileAFingerRemains`, все тесты порядка | ✅ |
| Не регистрировать повтор при повторной обработке события | JVM: `duplicate up event does not commit twice`, `replaying every event of a cycle twice still commits once` | ✅ |
| Значение имеет только итоговая комбинация (не длительность/порядок/пауза) | JVM: `chord timing is reported but never influences the mask`; `slidingFingerKeepsTheKeyItLandedOn`; `twoFingersOnOneKeyCountOnce` | ✅ |
| Границы клавиш | `keyColumnsSplitThePadIntoEqualFifths` — точки у внутренних краёв каждой колонки | ✅ |

| **Итого** | **180** | **180** |

Инструментальный набор прогнан дважды подряд без сбоев (стабильность).

Новые тесты на исправления после ревью дополнительно проверены мутационно: при временно
откатанном исправлении они падают (двойное «Готово», восстановление id новой заметки).

Найдено и исправлено в ходе тестирования на эмуляторе:

* При первом скрытии системных панелей Android показывает разовую подсказку «Viewing full
  screen» поверх центра экрана; пока она видна, касания K2–K4 уходят в неё. Это поведение
  системы (повторно не показывается после «ОК»). В сквозных тестах подсказка помечается как
  подтверждённая; в README добавлено предупреждение для первого запуска.
* По итогам код-ревью: спецклавиши больше не рекомпозируются при нажатии (подсветка — в фазе
  отрисовки); исключение системного жеста «Назад» сосредоточено на аккордной панели (лимит
  Android ≈200 dp на край); повторное «Готово» больше не дублирует экран списка.
* Espresso 3.5 (транзитивно из Compose UI Test) не работает на новых версиях Android
  (`InputManager.getInstance` удалён) — тестовый стек обновлён до androidx.test 1.7 / Espresso 3.7.
